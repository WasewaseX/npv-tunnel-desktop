# 1.1.1 — the review, closed point by point

Released as **v1.1.1** (tag `v1.1.1`, release id `444265363`, published 2026-11-13T13:30Z).
CI green on every commit; the tag was cut from `c1cb50b`.

## The four findings that mattered

| # | Finding | What the code did in 1.1.0 | What it does now |
|---|---|---|---|
| 1 | The engine's plaintext config persisted | One fixed runtime path, deleted on stop — so a live credential sat on disk for the whole session, and forever after a crash | Per-session directory `runtime/session-<guid>` (`0700`, owner-only ACL), written immediately before launch, **overwritten and deleted as soon as the engine reports its local endpoints listening**; leftovers from a killed session swept at startup; `SecretShredder` overwrites, flushes, renames, deletes — no `File.Delete` |
| 2 | A sidecar digest could overrule the build | `ENGINE.sha256` next to the binary was the authority, so replacing the binary *and* its sidecar made an unknown engine trusted | `EngineIntegrity.Known` pins every shipped engine's SHA-256 **into the assembly**; a sidecar that agrees with a mismatched binary is reported as tampering. The window runs the bundled engine only; the CLI needs an explicit `--trust-engine` and says the pin did not cover it |
| 3 | Hostnames walked past the private-endpoint check | `ConfigAudit` looked at the literal string; a config naming a host that resolves to `192.168.1.1` or `169.254.169.254` was dialled. The WPF app ran **no audit at all** | `EndpointResolver` resolves once, classifies every answer (loopback/RFC1918/CGNAT/link-local/ULA/documentation), refuses the profile if **any** answer is private (rebinding is refused, not averaged), and pins a healthy name via `dns.hosts` so the engine dials the audited address. The window runs the same path |
| 4 | The real-sample test skipped silently; warnings were noise | `return` when `NPVT_REAL_SAMPLE` was unset; 174 compiler warnings, nothing failed on them | `[SkippableFact]` (visible skip) + CI downloads the upstream container **pinned by commit and digest** on both OS jobs; a committed sanitised fixture (17 profiles, every endpoint replaced) always runs; `TreatWarningsAsErrors` + recommended analyzers, **zero warnings**, `dotnet format --verify-no-changes` in CI |

## The work, as tasks

1. `src/NpvTunnel.Core/EngineIntegrity.cs` — pins, bundled/custom verification, tamper wording.
2. Window runs the bundled engine only; a stale custom path in settings is logged and ignored.
3. CLI `--trust-engine` gate, `IsCustom`, exit 1 when a binary it was pointed at is refused.
4. `src/NpvTunnel.Core/SecretShredder.cs` — shred file/directory, stale sweep, `0600`.
5. `src/NpvTunnel.App/Services/WindowsAcl.cs` — owner-only ACL for directory and file.
6. App: per-session dir, shred after listening, cleanup on stop and on failure, startup sweep (`SweepStaleRuntimeFiles`).
7. CLI: shred on dispose, `Ctrl-C` included; no leftover `config.json` after `check`.
8. `src/NpvTunnel.Core/EndpointResolver.cs` — async/sync resolve, `Classify`, `PinCandidate`, literal detection, `AddressScope.IsPrivate`.
9. `ConfigAudit.Review(profile, resolution)` — refuses names resolving into private/documentation space; warns when unresolvable; literal-IP path now delegates to one classifier.
10. `EngineOptions.PinResolvedEndpoint` / `PinnedEndpointAddress`; `XrayConfigBuilder` emits `dns.hosts`.
11. Window `ConnectAsync`: resolve → audit → refuse/block → pin → build (was: build only).
12. `npvtunnel show/check/connect/config`: resolve, audit, pin; `check` prints `endpoint` and `pinned`.
13. `tests/fixtures/vendor-channel-sanitized.npvt` — real container shape, 17 profiles, fake endpoints/credentials; always-running test asserts all of it, including that the file does not mention the real host.
14. Real-sample test → `[SkippableFact]`; CI fetches `raw.githubusercontent.com/…/3c11306…/testdata/cfg.npvt`, verifies `28dbb6fe…`, exports `NPVT_REAL_SAMPLE` (bash + pwsh).
15. `Directory.Build.props`: `TreatWarningsAsErrors`, `EnforceCodeStyleInBuild`, `AnalysisLevel latest-recommended`; 174 warnings fixed (nullable, CS4014, plus CA1305 culture format and CA1845 `Substring`); `.editorconfig` documents the five style rules deliberately off.
16. `dotnet format` whitespace normalisation (8 files) with a CI gate, and the same gate in `scripts/build.ps1`.
17. `EnginePinDriftTests` — the digest lives in three places (`EngineIntegrity`, `EngineManifest`, `scripts/publish-linux.ps1`); all three are compared, so a release cannot ship an engine the app then refuses.
18. Docs: three new SECURITY.md sections (*Not persisting the plaintext*, *The engine binary*, the DNS-pin subsection), README Security/Testing, `docs/CI.md` ("What the pipeline refuses to skip"), a full 1.1.1 CHANGELOG entry.
19. Version 1.1.1, tag, Release workflow (all three jobs green), release notes rewritten to lead with the security fixes; the Notes template now links the CHANGELOG.
20. Hygiene: `editorconfig-checker` clean, `gitleaks` clean (`EngineIntegrity` digests moved into named constants; `.gitleaksignore` records the three false positives from the commit that introduced the old layout).

## Honest limits

* The config file is in the clear **while the engine starts**. Closing that needs stdin-binding or a pipe, which is not implemented.
* The window cannot run a different engine, by design; someone who needs to must use the CLI with `--trust-engine`.
* System-proxy mode is still not a VPN, and there is still no code-signing certificate.
